01

Type slowly so the viewer reads it. Make it real and specific — city, guest count, cuisine, time.

02
Narrate the tool calls as they happen
Show the agent thinking. Point at each tool call in your UI — "here it's calling search_restaurants_dineout on the Dineout server, simultaneously calling get_addresses on Food." This proves you understand the MCP internals.
03
Show the split-screen confirmation
Your UI should show Dineout booking + Food cart side-by-side before confirmation. One button. "Confirm both." This is the WOW moment — the user never had to switch between apps.
04
End with the architecture slide — 30 seconds
Show your agent flow diagram. Name the specific tools. Say "multi-turn cart state" and "non-idempotent order placement with check-then-retry." These are exact phrases from Swiggy's docs. They'll know you read deeply.
"The agent handles cart conflicts, retries non-idempotent order placements safely, and always re-fetches cart state before confirming — because the user could've edited in the Swiggy app."
